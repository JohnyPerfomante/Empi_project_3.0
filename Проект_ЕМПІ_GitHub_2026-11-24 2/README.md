# Освітній процес

Підсистема лінгвістичного аналізу відкритих відповідей студентів для ІПЗ і КН. Викладач публікує питання з еталонами й критеріями, студент надсилає відповідь, локальний NLP формує рекомендацію. Викладач ухвалює рішення й може затвердити формулювання для наступних перевірок.


## Оновлена збірка для GitHub від 24 листопада 2026 року

У цій папці **99 файлів**, ураховуючи приховані службові файли. Розпакуйте зовнішній ZIP
і завантажте вміст цієї папки в корінь репозиторію одним пакетом. Сам ZIP у репозиторій
завантажувати не потрібно: GitHub не розпаковує завантажені архіви автоматично.
Перед заміною старої версії приберіть із репозиторію застарілі файли, яких немає в цій збірці.
Для завантаження через браузер включіть також `.github`, `.env.example`, `.gitignore`,
`.dockerignore` та `.gitattributes`. Перевірте, що `docker-compose.yml` розташований у корені репозиторію.
Для браузерного завантаження беріть чисту папку із зовнішнього ZIP до виконання `configure`
чи `extras`. Після локального налаштування публікуйте зміни через Git або GitHub Desktop:
браузер не застосовує `.gitignore` до файлів, які ви перетягуєте у форму завантаження.

Увесь робочий код API, NLP, воркера, React, міграції та демонстраційний банк доступні
без розпакування внутрішнього архіву. Збережено реєстрацію студентів і викладачів,
окремих викладачів дисциплін, два різні еталони, змістову перевірку з формулами
та стовпчиковий графік точності відповідей.

Уключено алгоритм **3.0.0**: перевірка змістового зв’язку для кожного еталона, нульовий
підсумок без підтвердженої відповідності, окремі B/G/F та причини в картці роботи.
**«Методика перевірки» доступна лише викладачам і адміністраторам**; студенти не бачать
її в меню та не мають доступу за прямим посиланням чи через API.

Тести, Makefile, сценарій експериментального оцінювання, презентацію, інструкцію Word,
доповідь і додаткову документацію збережено
без змін у `development-extras.zip`. Для їх відновлення після клонування:

```bash
python3 project.py verify
python3 project.py extras
```

Відновлені матеріали виключені з Git через `.gitignore`, тому повторний `git add .`
зберігає компактну структуру. GitHub Actions відновлює їх автоматично перед перевірками.
Для зміни файлів тестів чи додаткової документації та публікації цих змін потрібно також
перепакувати відповідні файли у внутрішньому ZIP і оновити контрольні суми в маніфесті.

Потрібні Docker із Compose v2 і Python 3.10+ для допоміжних команд. У Windows використовуйте
`py -3` замість `python3`. Вебзастосунок запускається в Docker із Python 3.12 та Node.js 22.
Особисті `.env`, паролі, локальна база, кеші та ваги моделей у публічний пакет не входять.
Ваги завантажуються під час першого запуску; діюча локальна версія проєкту й її дані збережені.

Якщо інша версія вже займає порти 8080 та 55432, створіть конфігурацію з іншими портами:

```bash
python3 project.py configure --web-port 8081 --db-port 55433
```

Ця збірка має окреме ім’я Docker Compose, власні образи та томи бази й моделей.
Не копіюйте стару `.env` поверх нової, якщо хочете зберегти незалежні середовища.

## Запуск через Docker

Потрібні Docker Engine або Docker Desktop із Compose v2, доступ до реєстру образів і Hugging Face для першого запуску. Для робочого середовища з моделлю MPNet виділіть Docker щонайменше 6 ГБ оперативної пам’яті та близько 8 ГБ дискового простору для образів, моделі й даних.

```bash
python3 project.py configure
```

Команда створить `.env` з випадковими паролями та JWT-ключем. Існуючий файл не перезаписується. Пароль демонстраційних акаунтів указаний у `DEMO_PASSWORD` цього локального файлу. У репозиторії `.env.example` не містить цих значень. Вебсервіс і PostgreSQL за замовчуванням доступні лише на loopback.

```bash
docker compose up -d --build
docker compose ps -a
docker compose exec -T api python -m scripts.seed_demo
```

- Вебінтерфейс — [127.0.0.1:8080](http://127.0.0.1:8080).
- REST API та інтерактивна документація — [Swagger UI](http://127.0.0.1:8080/api/docs).
- За першого запуску `models` завантажує локальні ваги в том `models`. Нормальний стан після запуску — `migrate` і `models` завершилися з кодом 0, `api`, `worker`, `web` і `db` працюють. Подання приймаються під час підготовки воркера.
- `docker compose logs -f models worker` показує прогрес моделі. Статус воркера також є в адміністративному кабінеті.
- `docker compose down` зупиняє процеси й зберігає томи. Для відновлення використайте `docker compose up -d` з тим самим `.env`.

## Змістова перевірка та формули

Розділ **Методика перевірки** (`/methodology`) містить формули косинусної подібності, Жаккара, покриття понять, зваженого індексу та вибору серед кількох еталонів із першоджерелами. Довжина не входить до формули індексу. Викладач відкриває фактичний розрахунок і порівняння всіх кандидатів у картці аналізу. Публікація з одним еталоном або двома копіями відхиляється.

Алгоритм **3.0.0** окремо перевіряє змістовий зв’язок кожного кандидата: `F = G × B`. Непідтверджена відповідність або критичне правило дає **0%**, навіть якщо модель повернула ненульовий косинус. У знімку видно початковий B, допуск G, причину та підсумок F. Правило працює з рубрикою понять і без неї для всіх питань. Перевірка всього демобанку зі справжньою моделлю: `docker compose exec -T worker python -m scripts.verify_relevance`.

Обґрунтування й обмеження: [методика оцінювання](docs/ASSESSMENT_METHOD.md). Діагностика зі справжньою моделлю: `docker compose exec -T worker python -m scripts.verify_review`.

Для середовища без демо заповніть `BOOTSTRAP_ADMIN_EMAIL` і `BOOTSTRAP_ADMIN_PASSWORD`, далі виконайте `docker compose exec -T api python -m scripts.bootstrap_admin`.

### Реєстрація власного облікового запису

На сторінці входу натисніть «Створити обліковий запис» або відкрийте `/register`. Вкажіть ім’я та прізвище, електронну пошту, роль студента чи викладача та двічі введіть власний пароль довжиною 12–128 символів. Після створення облікового запису система відкриє форму входу з вашою поштою.

Реєстрація одразу активує обліковий запис. Для роботи з навчальними матеріалами адміністратор призначає викладачу курси або зараховує студента до курсу та групи. Самостійна реєстрація доступна для ролей `student` і `teacher`. Адміністратор створюється через bootstrap або чинним адміністратором.

`REGISTRATION_LIMIT` задає кількість спроб за 10-хвилинне вікно для однієї пошти. Ліміт мережевого клієнта утричі більший. Початкове значення — 5.

## Розробка

Потрібні Python 3.12, Node.js 20.19+ або 22, PostgreSQL 16+ із pgvector. Для локального Python використайте `DATABASE_URL` із `.env`. `DB_PORT` у Compose і порт у `DATABASE_URL` для запуску з хоста мають збігатися. Compose складає внутрішній DSN з `POSTGRES_*`. Якщо значення містить символи URI, потрібно передати коректно закодований DSN через перевизначення Compose.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e './backend[nlp,test]'
docker compose up -d db
alembic -c backend/alembic.ini upgrade head
(cd backend && python -m scripts.prepare_models)
(cd backend && python -m scripts.seed_demo)
uvicorn app.main:app --host 127.0.0.1 --no-access-log
```

В окремих терміналах, з активованим venv для воркера:

```bash
python -m app.worker
```

```bash
cd frontend
npm ci
npm run dev
```

## Перевірки

Спочатку відновіть тести: `python3 project.py extras`.

```bash
docker compose exec -T db createdb -U empi empi_test
TEST_DATABASE_URL=postgresql+psycopg://empi:empi@127.0.0.1:55432/empi_test \
  RUN_REAL_NLP=1 pytest -q backend/tests
npm --prefix frontend test
npm --prefix frontend run build
(cd frontend && npx playwright install chromium)
E2E_PASSWORD='<DEMO_PASSWORD>' npm --prefix frontend run e2e
```

Інтеграційні тести очищають лише явно вказану тестову БД із суфіксом `_test`. Для Playwright потрібні запущена система й seed. За замовчуванням він працює через порт 8080 і створює власні тестові записи. Змінні `E2E_BASE_URL` та `PLAYWRIGHT_CHROMIUM_EXECUTABLE` дозволяють указати іншу адресу й локальний браузер. CI запускає backend із тестовим NLP-провайдером. Окремий тест із `RUN_REAL_NLP=1` використовує кешовані ваги Stanza й MPNet.

Фактичні результати запуску перевірок наведено в [протоколі](docs/TESTING.md).

## Перенесення власних даних

Для приватної резервної копії цієї збірки:

```bash
python3 project.py backup .local/database.dump
```

Для перенесення даних з іншої локальної версії запустіть у її папці команду нижче.
Вона створює копію у локальній папці, яку не можна завантажувати на GitHub:

```bash
mkdir -p .local
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom --no-owner --no-privileges' > .local/database.dump
```

Перед першим запуском нової бази виконайте в папці цієї збірки:

```bash
python3 project.py configure
docker compose up -d db
python3 project.py restore /absolute/path/to/database.dump
docker compose up -d --build
docker compose exec -T api python -m scripts.upgrade_review_data
docker compose exec -T api python -m scripts.reanalyze_unreviewed
```

Відновлення дозволене лише в порожню базу зі зупиненими API й воркером.
Паролі існуючих користувачів зберігаються. Якщо база вже містить таблиці,
команда відмовиться відновлювати дані, щоб нічого не перезаписати.
`reanalyze_unreviewed` додає нову версію аналізу тільки застарілим роботам без ручного рішення;
попередні аналізи й рішення зберігаються. Повторний запуск не дублює вже актуальні роботи.
Не публікуйте резервні копії разом із вихідним кодом.
