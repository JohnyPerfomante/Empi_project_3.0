# Методика змістової перевірки відповідей

Версія алгоритму **3.0.0**. Правила застосовуються до всіх питань і дисциплін. На сайті відкрийте **Методика перевірки** (`/methodology`). Викладач у картці подання відкриває **Розрахунок і порівняння еталонів**, щоб побачити початкові метрики, перевірку змістового зв’язку та підсумок для кожного кандидата.

## Що змінилося

Невелика косинусна подібність можлива навіть між сторонніми текстами. Вона не є відсотком правильності. У версії 2.0.0 така подібність прямо входила до зваженого індексу. У версії 3.0.0 окреме правило G перевіряє, чи є достатній змістовий зв’язок із конкретним еталоном. Якщо підтвердження немає, кандидат дає **0%**, незалежно від ненульової початкової подібності.

Наприклад, відповідь **«Користувач вводить відповідь»** на **«Що таке REST API?»** не пояснює ресурси, єдиний інтерфейс або stateless. Спільні загальні слова не підтверджують знання теми. Ця сама перевірка діє для інших питань, а не є спеціальним винятком для REST API.

## Еталони та нормалізація

Публікація потребує щонайменше **двох різних еталонів**. Варіації беруть участь лише після затвердження викладачем. Незатверджені формулювання не впливають на результат.

Працюють локальні багатомовна `paraphrase-multilingual-mpnet-base-v2` та українська Stanza. Відповідь порівнюється з усіма еталонами та затвердженими варіаціями цього питання. Кожна варіація успадковує рубрику свого еталона. Hash-провайдер дозволений тільки в `APP_ENV=test`.

**Кількість символів не входить до формули відповідності.** Довжина є лише умовою допустимого введення. Повторення слів не збільшує множину лем і не замінює перевірку змісту.

## 1 Семантична подібність

```text
S_j = clip((u · v_j) / (||u|| · ||v_j||), 0, 1)
```

u = E(A) — вектор відповіді; v_j = E(R_j) — вектор кандидата. Для нульового вектора S_j = 0. Обмеження від’ємного значення нулем — правило проєкту. Довгі тексти розбиваються за токенами; вектори частин усереднюються й нормалізуються.

Джерела: [Reimers і Gurevych 2019 — Sentence-BERT](https://aclanthology.org/D19-1410/), [офіційна документація Sentence Transformers про STS](https://www.sbert.net/docs/sentence_transformer/usage/semantic_textual_similarity.html), [картка використаної моделі](https://huggingface.co/sentence-transformers/paraphrase-multilingual-mpnet-base-v2). Ці джерела описують порівняння текстів, а не готову формулу оцінювання студентів.

## 2 Лексична подібність

```text
L_j = |T(A) ∩ T(R_j)| / |T(A) ∪ T(R_j)|
```

T — множина змістових лем. Відсіюються PUNCT, SYM, ADP, AUX, CCONJ, SCONJ, DET, PRON, PART; заперечення зберігаються. Для порожнього об’єднання L_j = 0. Загальні слова можуть залишатися в цій допоміжній метриці, але самі не задовольняють перевірку G.

Джерела: коефіцієнт Жаккара у [Manning, Raghavan і Schütze — Introduction to Information Retrieval](https://nlp.stanford.edu/IR-book/html/htmledition/near-duplicates-and-shingling-1.html); морфологія у [Qi et al. 2020 — Stanza](https://aclanthology.org/2020.acl-demos.14/). Використання множин лем і перелік відсіяних частин мови — адаптація проєкту.

## 3 Покриття понять

```text
C_j = Σ_i(w_i · I_i) / Σ_i(w_i)
```

Викладач задає поняття, синоніми, ваги w_i > 0 та обов’язковість. I_i = 1, якщо знайдено поняття або заданий синонім як послідовність лем чи точних словоформ; інакше 0. Це зберігає правильні словоформи за неоднозначної лематизації. Без рубрики C_j = null. Покриття — власна зважена рубрика проєкту.

## 4 Початкова зважена подібність

```text
B_j = a·S_j + b·L_j + c·C_j,  a+b+c = 1
Без рубрики: B_j = (a·S_j + b·L_j)/(a+b)
```

Початкові ваги: a = 0.72, b = 0.08, c = 0.20. Використовуються налаштування конкретного аналізу. B_j ще не є підсумком: ненульовий B_j може бути обнулений перевіркою G_j.

## 5 Перевірка змістового зв’язку та підсумок

```text
D_j = (T(A) ∩ T(R_j)) \ (загальні слова ∪ заперечення)
G_j = 1, якщо S_j ≥ 0.30
            і (C_j > 0 або |D_j| ≥ 2 або S_j ≥ 0.80)
            і немає критичного правила K
Інакше G_j = 0
F_j = G_j · B_j
```

D_j містить спільні предметні леми. Слова «відповідь», «питання», «користувач», «система», «дані» та інші загальні слова не є самостійним лексичним доказом зв’язку. Повний перелік міститься в `GENERIC_CONTENT_TERMS` у `backend/app/nlp/methodology.py` і зберігається у знімку параметрів аналізу.

Знайдене поняття або синонім є явним підтвердженням; за відсутності рубрики можна використати дві предметні леми. Сильна семантична подібність S_j ≥ 0.80 дозволяє розглядати перефразування без буквальних збігів. Водночас дуже низька семантика S_j < 0.30 відсіює механічне додавання ключових слів у сторонній текст.

K — збіг критичного правила, заданого викладачем у будь-якому еталоні питання. Ці правила застосовуються до всіх кандидатів, тому інший еталон не дозволяє обійти критичну суперечність. За K підсумок кандидата дорівнює нулю навіть за високої початкової подібності.

Пороги 0.30 і 0.80, мінімум дві предметні леми, загальний словник, покриття, ваги й логіка G — **власні інженерні правила проєкту**. Вони не запозичені як формула оцінки з SBERT і не є доведеними ймовірностями. Категорії використовують окремі налаштування T_low і T_high; зміна цих порогів не вимикає G.

Арифметичний приклад сторонньої відповіді з рубрикою:

```text
S = 0.24; L = 0; C = 0
B = 0.72·0.24 = 0.1728
G = 0
F = 0·0.1728 = 0%
```

Це пояснювальні числа, а не обіцянка конкретного косинуса для кожного запуску моделі. У картці відповіді наведені фактичні значення.

## 6 Кілька еталонів і рекомендація

```text
j* = argmax_j F_j
F = F_j*
```

B_j, G_j та F_j обчислюються окремо для кожного еталона й затвердженої варіації. Вибирається найбільший підсумковий F_j; показники різних формулювань не додаються. За однакових F_j перевага у більшого S_j, потім L_j. Якщо всі кандидати відсіяні, результат дорівнює 0%.

Категорії:

1. G = 0 → 0% і LOW_MATCH незалежно від налаштувань категорій.
2. За G = 1, якщо F < T_low → LOW_MATCH.
3. За G = 1 пропущене обов’язкове поняття, нове заперечення або F < T_high → NEEDS_REVIEW.
4. Решта → HIGH_MATCH.

Початкові пороги категорій 0.39 і 0.79; курс може їх перевизначати. Нове заперечення без явного критичного правила є приводом для перевірки, а не універсальним доказом хибності. Нуль означає, що алгоритм не підтвердив відповідність за своїми правилами. Довільні фактичні помилки та логічні суперечності потребують належної рубрики й рішення викладача. Остаточну оцінку ухвалює викладач.

## Відтворення та історія

```bash
docker compose exec -T worker python -m scripts.verify_review
docker compose exec -T worker python -m scripts.verify_relevance
docker compose exec -T worker python -m scripts.verify_reference_materials
```

`verify_relevance` перевіряє кожне з 50 демонстраційних питань: сторонні фрази з рубрикою й без неї, правильне перефразування, часткову відповідь і обидва еталони. Це регресійний корпус розробника, а не незалежна оцінка загальної точності на студентських роботах. Сценарій нічого не змінює в базі.

Кожний результат зберігає версію 3.0.0, модель, ваги, пороги, правило змістового зв’язку, початковий B_j, допуск G_j, причину та F_j для всіх кандидатів. Старі аналізи й рішення не видаляються. Для ручного оновлення старої роботи є **Повторити аналіз**. Команда `python -m scripts.reanalyze_unreviewed` ставить у чергу лише застарілі роботи без рішення викладача; повторний запуск не дублює чергу й не змінює перевірені роботи.

## Викладачі дисциплін

Методика спільна для всіх викладачів. Доступ до курсів, питань, робіт і звітів обмежений активними призначеннями. Сім демонстраційних дисциплін мають сім окремих викладачів. Історичне авторство та ручні рішення зберігаються.
